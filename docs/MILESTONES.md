# 本体工程工作台里程碑与执行计划

版本：0.2｜更新：2026-09-06｜状态：规划基线，所有里程碑未开始

产品范围见 [PRD](PRD.md)。本文件负责排期、工作包、资源、依赖、阶段验收和变更取舍；不表示已创建外部项目任务或已经开工。

## 1. 排期基线

- W1 是实际启动周；未指定开始日期，因此使用相对周，不输出虚假的承诺日期。
- 团队：4名全职工程师，另有0.3–0.5 FTE产品/FDE负责人和每周2–4小时领域专家。
- 总工程容量：4人 × 24周 = 96人周；安排72人周功能工作，24人周用于联调、测试、缺陷与客户反馈，占容量25%。
- 工程师共同承担测试，不假定另有专职QA、设计师或运维团队。
- 每两周演示一次可使用流程，每个阶段至少一次门槛评审；演示必须记录样本、版本、结果和问题。
- 可并行开发后续适配工作，但上阶段门槛未通过，不能宣称下一阶段产品已交付。

| Owner代号 | 主责 | 协作 |
|---|---|---|
| A | 前端、工作台交互、对象与模板 | B提供API，C提供样例和语义状态 |
| B | 技术统筹、项目、版本、评审、权限、动作 | A、C、D |

上述为待落实的职责分配，不是已确认到岗人员。人数、可用时间或客户条件变化后，保留依赖顺序并重估工期，不能简单按人数线性缩短。

## 4. 统一验收规则

每个门槛记录：版本/提交标识、输入快照、插件/模型版本、测试步骤、期望与实际、缺陷单、验收角色、日期。实际证据在实现后归档，本规划不预填“通过”。

- 已知阻断或严重缺陷、跨项目泄漏、关键身份/关系错配、未关闭发布门槛错误不可豁免。
- 非关键字段缺口须由P/E记录原因、影响、替代方式与后续计划，不能靠高总体比例掩盖关键错误。
- SHACL、映射测试与业务正确性单独验收。
- LLM生成差异采用候选质量回归；产物重放使用已审定快照。
- 发布回滚只切换本体/映射/视图绑定；数据恢复与业务补偿各自记录。
- 通过门槛后才能标为该阶段完成；增加功能数量不能替代门槛证据。

用一个小型制造样例验证选型与契约，避免先建设大量界面后发现引擎不满足要求。输入为现有PRD、用例假设、获准使用的模型和开发环境。

| M0-02 | Project/Evidence/Version/Mapping/Release基础契约，预留View/Action边界 | B+C | M0-01 | FR-02、FR-09、FR-12 |
| M0-03 | Cordis加载、依赖缺失、卸载、任务取消及跨进程调用验证 | D+B | M0-02 | FR-12 |

### 交付物

- 用例卡与人工标定查询；合成/脱敏样例及来源说明。
- 服务schema、错误约定、稳定ID与版本策略。
- 可运行技术样例、依赖版本清单和支持能力矩阵。
- FDE核心流程原型、技术决策记录（ADR）、风险表。

### 演示与退出条件

1. CSV → 人工审定本体快照 → 映射 → SHACL → Turtle/JSON-LD与报告。
2. 固定快照重放结果一致；重新调用LLM不作为相同哈希要求。
3. 明确不支持的OWL/SHACL构造并给出错误报告；不静默降级。
4. 缺依赖插件无法错误启动；卸载后无残留监听/计时器；在途任务被结束或安全排空。
5. Python调用超时/失败向工作台返回可理解错误，任务状态可恢复。
6. 确认主要选型可用；不满足时有替代适配器或缩小范围的决策，不能直接进入开发而隐藏风险。

验收：P/B/C/D；用例由E确认。M0替代方案如造成后续工作量变化，必须重估剩余人周。

2名未参与开发的FDE可以完成一个固定项目的全流程。范围为单租户多项目、CSV/XLSX+文本/Markdown+PostgreSQL、一个行业场景、1,000条以内对象预览、3个验收查询。

### 交付物

- FDE工作台MVP、一个质量追溯行业样例、3个固定查询。
- 最小插件集合、字段画像、映射测试、证据和版本审计。
- 本体包、安装说明、环境检查和已知限制。
- 2名FDE的操作时间/返工记录及质量门槛报告。

### 演示剧本

FDE建项目 → 导入质量Excel与设备PostgreSQL → 从证据生成候选 → 修正设备/批次身份 → 运行3条查询 → 提交/评审批次 → 生成包 → 在干净测试环境安装 → 对照查询结果。

### 退出条件

- 两名非开发FDE分别独立完成；固定输入条件下首个可评审版本≤1工作日，记录每步主动操作与系统等待。
- 100%已发布定义和关键映射有证据或人工确认。
- 关键标识/关联键映射100%；3个验收查询匹配人工期望；阻断级校验0。
- 故意注入重复键、错误单位、断链接时可定位失败源并修复。
- 旧基线、过期审批或权限不足不能合并/发布；跨项目读取/导出/任务负例全部通过。
- 审定制品在干净环境重放一致，secret不入包；最小本体/映射/查询包可导入新项目，重新绑定项目作用域，按业务键比较结果一致。
- 依赖缺失的preflight能阻断部署；任务失败/取消具备可读状态。
- 不能用“开发人员手工改数据库后演示成功”替代独立FDE完成。

### 不在M1

OpenMetadata、PDF/DOCX/OCR自动解析、动作执行、通用图画布、完整分支合并、Kubernetes、完全离线分发和对象属性细权限。

MVP应优先表单/表格与基础关系图。日期受压时削减视觉编辑复杂度，不能削减证据、关键映射、评审、隔离和交付重放。

## 7. M2：对象应用MVP+（W11–14）

### 目标与范围

将已验证本体转为客户可理解的对象页面与演示流程。复用一套组件生成3个模板，只完成1条沙箱动作闭环。OpenMetadata作为可选目录插件首次接入。

### 工作包

| 编号 | 工作包 | Owner | 依赖 | 对应FR |
|---|---|---|---|---|
| M2-01 | ObjectView：属性、来源、关联、时间线、保存视图 | A+C | M1查询/版本 | FR-08、FR-14 |
| M2-02 | 设备详情、质量收件箱、审核表单三个配置模板 | A+B | M2-01 | FR-14、FR-16 |
| M2-03 | ActionType参数/权限/前置校验/预览/幂等/审计与样例沙箱 | B+C | M1权限、M2-01 | FR-15 |
| M2-04 | OpenMetadata只读表字段/源标识/标签适配与数据关联 | D | 可用样例环境 | FR-03 |
| M2-05 | 用例包锁定视图/动作/能力映射，跨项目配置重放 | D+B | M2-02、M2-03 | FR-10、FR-11、FR-16 |
| M2-06 | 命令面板、批量体验和FDE演示走查 | A+P | M2-01～05 | FR-01、FR-14 |

### 交付物与演示

从同一本体配置生成3个模板；在质量收件箱选择缺陷、查看设备和来源、预览并提交一个沙箱处理任务；导入包到新项目再运行。

同时展示OpenMetadata字段到本体映射，说明业务行数据来自另一个获准连接器。无OpenMetadata时基础产品完整可用。

### 退出条件

- 三模板共用组件和契约；每个模板至少一份可验证样例，无需改平台核心代码。
- 一条沙箱动作链跑通；权限/前置校验失败不变更状态。
- 项目/动作版本作用域内，同幂等键相同请求不重复执行；同键不同输入或目标返回冲突。返回缓存结果仍检查当前权限；审批后输入/对象版本变化需重新验证。
- 对象视图与查询共用项目/角色权限，不绕过查询授权；细粒度属性遮蔽在M3验收。
- OpenMetadata适配能区分连接失败、无权限、空数据；版本范围写入兼容清单。
- 新项目导入视图/动作包与样例成功，客户上下文不串项目。
- 数据模型和业务动作运行契约分别可检查，OWL导出不冒充可执行应用包。

### 控制范围

不做完整拖拽App Builder、不做生产写回、不做完整OpenMetadata血缘/治理回写。PDF/DOCX文本解析仅为有余量时的候选，不是门槛。

## 8. M3：客户试点（W15–20）

### 目标与输入

在一个客户环境交付质量追溯闭环。客户数据与接入条件最迟W14就绪，W18末冻结试点必需范围，W19–20用于至少连续两周观察，关键用户可参与反馈。

M3容量拆分：W15–18共有16人周，其中13用于试点必需功能、3用于安装/联调/验证；W19–20共有8人周，其中5用于观察/缺陷/验收、3仅用于不改变试点路径的文档和非阻断体验完善。不得在观察期继续补齐尚未具备的接入、权限或部署门槛。

W18前必须具备：两类源的限定接入、关键映射、只读批同步及漂移报告、一条内部任务链、工厂/产线范围与必要属性遮蔽、基础依赖影响列表、离线安装和版本切换。完整健康趋势图、交互影响画布和额外规则延后；M3只需能定位影响和运行失败。新增必需功能超过13功能人周时，减少经批准范围或重排观察开始日期，不能挤占两周观察期。

两类数据源可以是SQL/接口 + 文件；若必须接MES/ERP，仅做约定实体和端点的有限适配，不把一个接口适配称为完整通用产品连接器。

### 交付物

- 客户用例包、两类数据源配置、现场映射与验证报告。
- 对象应用与平台内部处理任务；源系统业务状态保持单独展示。
- 批同步、漂移提案、健康/影响视图、范围权限。
- 离线安装介质/清单、版本切换与初步备份路径、培训和试点日志。

### 演示剧本

客户管理员安装 → FDE加载客户包 → 导入/同步约50字段和10,000对象 → 检查批次/工序/设备质量链 → 生成内部处理任务 → 注入新字段或枚举漂移 → 查看受影响映射并提交提案 → 升级一次再切换旧版 → 由管理员定位一个故意注入的错误。

### 退出条件

- 客户确认1个用例、3个查询结果；抽检100条关键对象/关系，关键身份、关联和业务状态100%符合人工记录；非关键差异有批准说明。
- 全部失败映射可定位；Schema Drift不自动修改已发布本体。
- 内部自动化有去重、暂停和执行日志；不访问未获准客户写入接口。
- 数据权限覆盖列表、搜索、聚合、导出、后台任务与制品；越权负例通过。
- 客户管理员在断外网条件下完成安装、查询、一次升级、查错；无本地模型时手工路径可用。
- 固定范围下本体/映射/视图版本绑定切换≤10分钟；不会声称撤销已执行动作。
- 累计连续2周试点观察，问题有Owner与处置记录；关键故障需修复并按影响重新观察。
- 客户接入或验收人缺席时，保留“试点待验收”状态，不能以内测代替客户签收。

### 控制范围

只支持当前客户批准的对象范围与少数规则，不做任意ABAC策略语言。自动化先做内部待办和站内通知；外部邮件、短信、生产写回另立需求。

## 12. 范围削减与变更规则

为保日期按以下顺序处理候选范围，不能悄悄降低质量门槛：

1. 延后PDF/DOCX自动提取与OCR，保留文字粘贴/文件索引。
2. 仅REST，延后GraphQL/MCP等额外协议。
3. OpenMetadata保表/字段/标识只读，延后完整血缘及回写。
4. 先Compose，延后Kubernetes标准发行和集群组件。
5. 锁一个存储/模型实现，保留接口，不建设第二套生产实现。
6. 保基线+乐观锁PR，延后三路合并、实时协作与复杂图编辑。
7. 三模板共用组件，只完成一个动作闭环；额外业务逻辑单独排期。

这些后置项多数已排除在基线；如果核心工作仍超容量，必须调整日期或减少经批准的核心范围，不能把“砍掉本来未承诺的功能”当成新增缓冲。

不能削减：证据、关键身份映射、项目隔离、基础审计、发布锁版、业务验证、适用阶段的恢复与权限门槛。

变更记录至少包含：提出人、价值、受影响FR/工作包、估算人周、替换项、风险、决定与批准日期。
